# FW-126.3 — równoważność ścieżki kalibracji prądu

**Status:** etap A i B **ZAKOŃCZONE**. Wynik: `NO ADC FIRES` — trigger CH3 nie napędza żadnego ADC przy MOE OFF. **STOP** przed implementacją.
**Data:** 2026-08-26
**Obraz:** DIAG `0.0432` (poprzednie 0.0431 = model „complete triple", wycofany)
**Zmiany w kalibracji, FOC, PI, Hallu, oknie próbkowania, progach, offsetach:** ŻADNE.

---

## Sprzeczność do wyjaśnienia

| Ścieżka | Warunki | Odczyt JDR |
|---|---|---|
| kalibracja startowa | MOE OFF, trigger **programowy** | ~1852 / 1879 / 1884 |
| neutral dwell (FW-126.2) | MOE ON, trigger **TIMER0_CH3** | −10 / −3 / +12 |

Powtarzalne: trzy niezależne rozruchy dały 1841/1866/1871, 1848/1874/1879, 1852/1879/1884.
P2P 15–19, niezależny verify zgodny do 1 LSB, MOE-off potwierdzone sprzętowo. To pomiar, nie szum.

## 1. Ścieżka kalibracji — faktyczny przebieg

`main()` → `phase_cal_collect_samples()` (`src/main.c`):

1. sprawdza `TIMER_CCHP(TIMER0) & POEN` — odrzuca próbę, jeśli mostek żyje; **nigdy nie rusza MOE**;
2. **przestawia źródło triggera**: ADC0 inserted → `ADC0_1_2_EXTTRIG_INSERTED_NONE`,
   ADC2 inserted → to samo (czyli trigger programowy) — na czas swojego wywołania;
3. maskuje `ADC0_1_IRQn` (produkcyjny handler kasuje tę samą flagę EOIC, którą pętla odpytuje);
4. pętla: `adc_software_trigger_enable(ADC0, INSERTED)` + to samo dla ADC2 → czeka na EOIC
   wszystkich trzech → czyta JDR w kolejności **A=ADC2, B=ADC1, C=ADC0** → kasuje EOIC;
5. przywraca `T0_CH3` jako źródło i odblokowuje przerwanie.

## 2. Ścieżka runtime — faktyczny przebieg

`adc_config()` ustawia i **zostawia**: ADC0 inserted ← `ADC0_1_EXTTRIG_INSERTED_T0_CH3`,
ADC2 inserted ← `ADC2_EXTTRIG_INSERTED_T0_CH3`, ADC1 inserted ← `NONE` (startuje jako slave
w trybie `ADC_DAUL_INSERTED_PARALLEL_REGULAL_FOLLOWUP_FAST`). `ADC0_1_IRQHandler` czyta te same
trzy JDR w tej samej kolejności.

## 3. Różnice konfiguracyjne — wynik audytu

Kolejność w `main()`: `nvic_config()` (990) → `timer0_config()` (993) → `adc_config()` (1002)
→ sonda FW-126.3 → kalibracja (~1180).

`timer0_config()` zostawia: **TIMER0 URUCHOMIONY** (`timer_enable`), CCR0/1/2 = `_T/2`,
CCR3 = `TRIGGER_DEFAULT` (3740), **MOE OFF** (`timer_primary_output_config(TIMER0, DISABLE)`).

| Element | Kalibracja | Runtime | Różni się? |
|---|---|---|---|
| źródło triggera inserted | **programowe** | **TIMER0_CH3** | **TAK — jedyna różnica** |
| MOE / POEN | OFF | ON (w dwellu) | tak, ale patrz niżej |
| TIMER0 licznik | uruchomiony | uruchomiony | nie |
| CCR0/1/2 | `_T/2` | `_T/2` | nie |
| CCR3 | 3740 | 3740 | nie |
| sekwencja inserted | ADC0/ADC1/ADC2, po 1 kanale | identyczna | nie |
| synchronizacja ADC0/ADC1 | dual inserted parallel | identyczna | nie |
| offsety sprzętowe (IOFF) | 2012 / 2028 / 2020 | identyczne | nie |
| czas próbkowania | 55,5 cyklu | identyczny | nie |
| kolejność odczytu JDR | A=ADC2, B=ADC1, C=ADC0 | identyczna | nie |
| własność EOIC | pętla odpytuje i kasuje, IRQ zamaskowane | IRQ | tak (mechanizm, nie moment) |

**Wniosek etapu A:** w oknie między `adc_config()` a kalibracją sprzęt jest **już dokładnie
w stanie, o który prosi etap B**: MOE off, timer chodzi, neutralne compare, żywy trigger CH3.
Kalibracja sama z tego wychodzi, przestawiając źródło na programowe. Zmienną jest **trigger**.

## 4. Premisa, którą etap B mierzy

Komentarz przy wywołaniu kalibracji twierdzi, że trigger sprzętowy CH3 **nie produkuje**
konwersji przy MOE OFF, i to jest powód istnienia triggera programowego. Audyt rejestrów mówi
inaczej: `POEN` bramkuje **stopień wyjściowy**, a nie `OC3REF` ani zdarzenie compare CH3, które
karmi ADC. Dodatkowo log FW-121.0B, na którym ta premisa stoi, pochodzi ze sweepu, o którym
jazda FW-126.2 pokazała później, że **nigdy się nie uzbroił** (state IDLE).

To jest teza do zmierzenia, nie do przyjęcia. Etap B ją rozstrzyga.

## 4a. WYNIK ETAPU B (log 2026-08-26 09:05, DIAG 0.0431)

Dwa niezależne odczyty `0x602E` w jednym cyklu zasilania, identyczne:

```text
samples 0   timeouts 1   waits 1   fresh 0
MOE off verified YES   TIMER0 running YES   CH3 3740
```

**Sonda ani razu nie zobaczyła jednocześnie ustawionych EOIC na ADC0+ADC1+ADC2** w oknie
2 000 000 iteracji (wielokrotność okresu PWM 62,5 µs).

**Moja hipoteza z §4 została OBALONA pomiarem.** Twierdziłem, że POEN bramkuje tylko stopień
wyjściowy, więc trigger CH3 powinien działać przy MOE OFF. Nie działa — premisa zapisana przy
wywołaniu kalibracji okazuje się zgodna z zachowaniem sprzętu.

**Czego ten pomiar NIE rozstrzyga.** Sonda czeka na koniunkcję trzech flag i nie zapisuje ich
osobno, więc nie odróżnia:
(a) braku jakichkolwiek konwersji wyzwalanych timerem przy MOE OFF, od
(b) sytuacji, w której ADC0/ADC2 konwertują, a ADC1 (slave trybu dual) nie kończy.
To jest luka w mojej instrumentacji, nie w danych. Werdykt w obu dekoderach został zawężony,
żeby nie twierdzić więcej, niż zmierzono.

**Konsekwencja dla karty:** trigger programowy jest jedynym sposobem próbkowania ciemnego
mostka, więc **ścieżka triggera NIE jest przyczyną** różnicy ~1850 vs ~0.
Kontrakt naprawy z §7 **nie wchodzi w życie**. STOP.

## 5. Etap B — sonda `0x602E`

`fw1263_probe_run()` (`src/main.c`, DIAG-only) uruchamia się **raz**, tuż przed kalibracją.
**Nie zmienia żadnej konfiguracji.** Odpytuje EOIC konwersji, które sprzęt już produkuje,
czyta te same trzy JDR w tej samej kolejności, kasuje flagi i powtarza 16 razy. Sprawdza POEN
przed i po. Raportuje: raw A/B/C, mean, mediana, min/max, spread, CNT/DIR, CH3, MOE, świeżość,
offsety i wartość skorygowaną.

Transport: read-only `0x602E`, 55 B, ta sama ramka i CRC co `0x602D`.

## 4b. WYNIK ETAPU B v2 — ROZSTRZYGNIĘCIE (log 2026-08-26 13:07, DIAG 0.0432, schemat 2)

```text
conditions: MOE off YES   TIMER0 running YES   CH3 3740   polls 2 000 000
reference : ADC0 event seen NO

  ADC  phase  events   n   median
  ADC0    C        0    0        0
  ADC1    B        0    0        0
  ADC2    A        0    0        0

VERDICT: NO ADC FIRES
```

**Żaden z trzech ADC nie zgłosił ani jednego zdarzenia EOIC** w 2 000 000 iteracji odpytywania,
przy potwierdzonym MOE OFF, uruchomionym TIMER0 i CH3 = 3740.

To rozstrzyga niejednoznaczność, której v1 nie potrafił rozwiązać: **nie chodzi o slave ADC1**.
Milczą wszystkie trzy. Premisa zapisana przy wywołaniu kalibracji jest w pełni potwierdzona,
a moja hipoteza z §4 (POEN bramkuje tylko stopień wyjściowy) **ostatecznie obalona pomiarem**.

**Wniosek:** trigger programowy jest jedynym sposobem próbkowania ciemnego mostka, więc
**ścieżka triggera NIE JEST przyczyną** różnicy ~1850 vs ~0. Kontrakt naprawy z §7 nie wchodzi
w życie. Przyczyny ~1850 należy szukać gdzie indziej — to zakres osobnej karty.

## 5a. PRZEBUDOWA MODELU (2026-08-26) — nie łatanie, wymiana

Pomiar v1 zwrócił `samples 0` i tym samym obalił **założenie, na którym stała sonda**:
że kryterium jest koniunkcja `ADC0_EOIC && ADC1_EOIC && ADC2_EOIC`. Koniunkcja nie potrafi
wskazać, który człon był fałszywy, a od tego zależał następny krok. Zgodnie z zasadą
architecture-first model został **zastąpiony**, nie obudowany wyjątkiem.

**Nowy model:** trzy niezależne strumienie zdarzeń, po jednym na ADC, z **ADC0 jako zdarzeniem
odniesienia** (master trybu dual, do niego podłączony jest trigger CH3). Każdy ADC jest
odpytywany, zapisywany i kasowany osobno; nic nie czeka na nic.

**Usunięte bez zamienników** (brak konsumenta w nowym modelu): licznik kompletnych trójek,
timeout per trójka, osobny licznik `fresh`, tablica `cnt[16]` z CNT per próbka, średnia
arytmetyczna `mean[]` (mediana jest odpowiedzią i zawsze się z nią zgadzała).

**Dodane** (każde odpowiada na pytanie, którego v1 nie umiał zadać): `events` per ADC,
`polls` (budżet odpytywania — bez tego „0 zdarzeń" jest nieograniczone), oraz jedno
`ref_cnt`/`ref_dir_down`/`ref_seen` dla pierwszego zdarzenia ADC0 zamiast szesnastu.

**Efekt na rozmiarze:** RAM 46456 → **46432 B** (−24), FLASH 153016 → **152808 B** (−208).
Prostszy model jest też mniejszy.

**Nowe drzewo decyzyjne** (schemat 2, w obu dekoderach):

| Zdarzenia | Werdykt | Znaczenie |
|---|---|---|
| żaden ADC | `NO ADC FIRES` | trigger CH3 nie napędza niczego przy MOE OFF |
| ADC0 = 0, inne > 0 | `MASTER SILENT` | fakt o routingu triggera, nie o mostku |
| ADC0 > 0, ADC1 lub ADC2 = 0 | `PARTIAL` | **to, czego v1 nie widział** — np. slave dual nie kończy |
| wszystkie > 0, mediany ≈ 0 | `ALL FIRE, READ ~0` | ścieżka programowa NIE jest równoważna |
| wszystkie > 0, mediany ≈ 1850 | `ALL FIRE, READ HIGH` | trigger uniewinniony → STOP |
| wszystkie > 0, pomiędzy | `ALL FIRE, MIXED` | nie forsować gałęzi |

Dekodery nadal czytają schemat 1, żeby log z 2026-08-26 pozostał czytelny — ale **firmware
diagnostyczne nie zawiera już starego modelu**.

## 6a. Co dalej — propozycje, NIC nie wdrożone

Kolejny krok musi rozstrzygnąć (a) vs (b) i dopiero potem szukać przyczyny ~1850. Najtańsze
możliwości, w kolejności inwazyjności — **żadna nie jest zaimplementowana**:

1. ~~Rozszerzyć sondę o stan flag EOIC~~ — **ZROBIONE inaczej**: cały model przepisany na
   zdarzenia per ADC (§5a). Rozstrzygnięcie (a) vs (b) wyjdzie z jazdy na `0.0432`.
2. Jeśli werdykt to `MASTER SILENT` albo `PARTIAL` — dopiero wtedy zrzut rejestrów
   ADC/TIMER, celowany w to, co pokaże pomiar. Nie wcześniej, nie „na wszelki wypadek".
3. Dopiero mając to — wrócić do pytania, dlaczego trigger programowy daje ~1850, skoro ta sama
   ścieżka JDR w dwellu daje ~0.

**Jeśli okaże się, że produkcyjna kalibracja stoi na błędnym modelu — nie łatamy jej.**
Następna zmiana ma być czystą wymianą z jawną transakcją akwizycji, bez utrzymywania
OLD CAL i NEW CAL obok siebie.

## 7. Kontrakt bezpiecznej naprawy — NIE OBOWIĄZUJE (wynik etapu B go nie uruchomił)

- kalibracja przełącza się na akwizycję wyzwalaną z TIMER0_CH3 przy MOE OFF;
- **nie zmienia** progu ±300, polityki fallback, offsetów sprzętowych ani wzmocnienia;
- MOE pozostaje OFF przez całą kalibrację, sprawdzane przed i po, jak dziś;
- wynik musi przejść ten sam niezależny self-test, który istnieje;
- osobny build + host testy + jazda; NORMAL musi zostać bit-identyczny.

Przy każdym innym wyniku sondy — STOP. Kalibracji z załączonym mostkiem nie wolno wdrożyć
bez osobnej analizy bezpieczeństwa.
